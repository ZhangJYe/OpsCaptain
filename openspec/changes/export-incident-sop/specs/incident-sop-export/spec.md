## Purpose

让运维人员将已完成的事故诊断沉淀为可下载、可复核、带完整时间信息的 Markdown SOP 草稿。

## ADDED Requirements

### Requirement: 从已创建事故导出 SOP 草稿

系统 SHALL 在已加载事故的结论区域提供导出 SOP 操作。导出的 Markdown MUST 包含事故标题和编号、服务或影响信息（如有）、实际诊断策略、根因结论、可复核证据、建议动作与事故轮次。

#### Scenario: 成功导出已完成事故

- **WHEN** 用户在已创建事故的结论区域选择导出 SOP
- **THEN** 浏览器下载一份包含该事故诊断内容的 Markdown 文件，且不修改事故记录

#### Scenario: 事故尚无最终结论

- **WHEN** 用户在尚未形成最终结论的已创建事故中选择导出 SOP
- **THEN** 系统仍导出当前可用的过程、证据和建议动作，并明确标示最终结论待补充

### Requirement: SOP 包含明确时间与人工复核边界

系统 SHALL 在 SOP 中记录事故创建时间、最近更新时间、完成时间（如可用）和导出时间。系统 MUST 将文件标识为“待人工复核的 SOP 草稿”，且不得将其表述为已批准或已执行的生产操作。

#### Scenario: 导出带日期记录的 SOP

- **WHEN** 用户导出任一已创建事故
- **THEN** 文件的元数据区包含创建、更新、完成（如有）和导出日期，并包含人工复核提示

### Requirement: 不可导出状态清晰可见

系统 MUST 在没有已加载事故时禁用或隐藏导出 SOP 操作，并向用户说明需要先从工作台创建或打开事故记录。

#### Scenario: 没有当前事故

- **WHEN** 用户打开空的事故记录视图
- **THEN** 系统不提供可执行的 SOP 导出操作
