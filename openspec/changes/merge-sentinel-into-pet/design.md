## Context

现有人偶与变更哨兵都是右下角浮层：人偶已具备位置持久化与拖动，哨兵已具备 SSE 事件、未读计数、事件摘要和展开面板。见 proposal.md 与 `pet-sentinel` 规格；本次不改变后端事件协议。

## Goals / Non-Goals

**Goals:**

- 由单一可拖动锚点承载人偶和哨兵入口，避免两个浮层竞争右下角。
- 将 Agent 情绪和哨兵状态分层，避免任一状态覆盖另一个。
- 复用现有事件列表、已读和清空行为，并让面板跟随人偶位置。

**Non-Goals:**

- 不改变事件 SSE、风险评估、事件存储或清空语义。
- 不把人偶改造成自动执行或审批入口。
- 不新增常驻监控大卡片或全局通知中心。

## Decisions

### 1. 人偶情绪与哨兵状态分离叠加

人偶图片和既有动画继续只表达 Agent 工作状态；哨兵以外圈、状态点、未读角标和短暂摘要表达事件状态。相比用哨兵状态替换人偶表情，该方案能同时表达“正在推理”与“有高风险变更”。

### 2. 由人偶容器持有哨兵交互

将事件面板的触发、锚定与拖动协调收敛到人偶容器，并复用事件面板内容。短点击切换面板，发生有效拖动时抑制点击；面板始终从人偶上方展开。相比保留两个独立浮层，可消除位置重叠与重复入口。

### 3. 新事件采用短暂气泡而非常驻标题条

有未读事件时，人偶上方只短暂展示最新服务和摘要；持续可见的信息仅保留风险色与数量角标。相比当前常驻哨兵触发器，这能维持主工作区的视觉安静。

## Risks / Trade-offs

- [用户不容易发现哨兵入口] → 保留明显的状态点、角标、hover 文案与无障碍标签。
- [拖动后点击误触] → 用移动阈值区分拖动与点击，并在拖动中禁止切换面板。
- [面板靠近窗口边缘溢出] → 根据人偶当前坐标自动选择上方/侧上方，并限制面板可视区域。
- [人偶被关闭] → 保留现有设置开关；人偶关闭时不渲染该入口，事件连接逻辑不受影响。

## Migration Plan

1. 提取可复用的哨兵面板内容与状态映射。
2. 将状态叠加、短暂摘要和点击/拖动协调接入人偶容器。
3. 从主布局移除独立的哨兵触发器，保留同一事件数据源。
4. 验证待命、未读、异常、拖动、展开和边界位置；回滚时恢复独立哨兵组件，不影响事件数据。
