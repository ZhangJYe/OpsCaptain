## Context

See proposal.md. 当前 recorded 回放已保证 case 隔离与标签边界，但真实模型输出会因代码块、说明文字或字段格式轻微偏差被直接拒绝；同时，评测结果未将模型服务故障与协议错误分开统计。

## Goals / Non-Goals

**Goals:**

- 兼容不改变 JSON 语义的常见展示包装。
- 保持严格 schema 与证据验证，拒绝语义不完整的输出。
- 让离线报告能区分模型服务、协议和图推理三类失败。
- 让服务默认配置启用结构化认知和状态转换，令模型分析可驱动候选细化与回溯。

**Non-Goals:**

- 不修改线上 AIOps 流程或降低线上结构化输出约束。
- 不把 recorded 回放变成生产准确率证明。
- 不补造、复用或暴露评测标签和原始遥测。

## Decisions

1. 在 GoS 结构化入口、规划和专家解析边界复用“单对象提取”，仅去除代码围栏及对象前后的非 JSON 包装；随后继续使用严格 JSON 解码和全部现有领域校验。服务启用结构化认知时同样使用该受限兼容，避免展示包装使线上图推理在入口阶段丢失有效提案。相比宽松地忽略未知字段或猜测字段，这不会让模型绕过证据约束。
2. 通过结构化的失败标签保留服务层错误（包括熔断）与协议解析错误；图引擎继续给出无进展降级，但评测汇总按底层原因优先归类。相比只读取最终 `no_progress_loop`，能够定位真正的质量瓶颈。
3. recorded profile 继续固定紧凑的步骤和 fast 模型，但从有效 GoS 配置读取模型调用超时；避免评测专用硬编码覆盖环境配置。
4. `manifest/config/config.yaml` 将结构化认知和状态转换设为开启，作为实际服务默认；`gos_engine.DefaultConfig()` 保持测试/显式装配的保守基线，防止未注入模型的单元测试意外发起外部调用。服务运行时统一经 `LoadAIOpsGOSConfig` 读取 manifest，因此不会形成两套线上行为。

## Risks / Trade-offs

- [提取器接受意外内容] → 只允许一个平衡的 JSON 对象，提取后严格解码并拒绝多个对象。
- [模型服务波动污染评测] → 单独计数并在报告中标注该批次不具备模型质量比较价值。
- [结构化流程增加调用成本] → 使用既有 plan/expert 调用预算、超时及 `ResultStatusDegraded` 降级；评测报告同时输出调用次数和阶段延迟。

## Migration Plan

1. 增加提取、分类和服务配置默认值测试。
2. 接入 recorded GoS 评测结果并验证既有评测不变。
3. 使用同一冻结集重跑；若模型服务错误占主导，保留结果为基础设施诊断而不宣称模型效果。
