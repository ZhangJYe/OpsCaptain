## Context

现有上传流程能够按用户来源保存资料并异步构建检索索引，但仅提供上传与单文件状态查询。资料元数据由本地上传存储维护，向量索引可以按资料来源清理，关键词检索索引可由索引服务重建。详见 proposal.md 与 `knowledge-base-management` 规格。

## Goals / Non-Goals

**Goals:**

- 提供一个以资料列表为核心的个人知识库页面，令上传、状态确认和资料删除在同一处完成。
- 将资料管理的用户范围严格绑定到认证用户，避免依赖前端传入的用户标识。
- 将删除定义为“检索清理优先”：只有检索内容清理成功后才删除文件与元数据，并重建关键词检索索引。

**Non-Goals:**

- 不在本次实现团队共享资料、文件夹、标签、版本历史或资料在线编辑。
- 不更改现有聊天附件上传入口；它继续复用相同的上传与索引能力。
- 不新增外部存储或队列依赖。

## Decisions

### 1. 以资料列表作为页面主体

知识库位于侧栏一级导航。页面顶部只保留“上传资料”这一主操作，列表行承载状态、时间和操作；点击行在右侧或窄屏抽屉中查看元数据。这让高频的确认资料是否可用的行为优先于低频详情。

备选方案是将上传入口继续留在工作台并仅新增弹窗。它无法提供持续的资料状态和删除操作，故不采用。

### 2. 将上传元数据扩展为管理记录

上传存储接口增加按来源前缀列出资料、按安全文件标识读取资料、删除资料原文件和元数据的能力。应用层从认证上下文计算个人来源前缀，控制器不直接访问存储。

资料列表 API 不暴露磁盘路径、内容哈希或其他用户资料。删除和重新索引接口仅接受资料标识，应用层验证其来源前缀。

### 3. 清理索引后再删除资料

删除流程先根据资料记录的来源字段删除向量索引，再删除原文件与元数据，并重建关键词检索索引。任一步骤失败均返回失败并保留资料记录，防止出现“页面已删但模型仍能检索”的假删除。

这不是跨存储事务：向量索引已清除但文件删除失败时，资料仍可再次尝试删除，重复的索引清理必须是幂等的。备选方案是先删文件；它会使重试无法取得来源信息，故不采用。

### 4. 仅允许重新索引失败资料

重新索引读取原文件并复用已有索引服务，将状态切换为索引中，再异步更新为已就绪或失败。限制为失败状态避免用户在仍在索引时制造并发任务，也避免覆盖已就绪资料。

## Risks / Trade-offs

- [本地文件存储在多实例中不可共享] → 本次沿用当前单实例约束；部署多副本前必须使用共享卷或存储适配器。
- [删除跨越向量与文件两类存储，无法完全原子化] → 使用检索清理优先、保留失败记录和幂等重试，避免对用户宣称已删除但仍可检索。
- [索引状态异步变化] → 前端轮询资料列表中仍处于索引中的记录，并在离开页面时停止轮询。

## Migration Plan

1. 部署新增接口与存储能力，保持现有上传接口兼容。
2. 部署前端知识库页面与导航入口。
3. 验证上传、索引完成、失败重试、跨用户隔离和删除后检索不再命中的流程。
4. 如需回滚，移除前端导航入口并停止调用新接口；既有上传资料和索引不受影响。
