## Purpose

为统一 Agent 入口提供可解释、可校验、可主动澄清的分层意图路由，使清晰请求快速分流、歧义请求利用有界会话状态消歧，并确保模型分类结果不能绕过高风险执行边界。

## ADDED Requirements

### Requirement: 原始请求保持为路由主输入

系统 SHALL 以未经 Memory 改写的原始用户 query 作为每次路由的主输入。系统 MAY 使用有界的结构化会话状态辅助校验，但 MUST NOT 使用长期记忆、自由文本摘要或历史回答替代原始 query。

#### Scenario: 历史内容与当前请求冲突

- **WHEN** 当前 query 是明确的知识问答，而历史会话曾进行故障诊断
- **THEN** 系统按当前 query 生成问答候选，不得仅因历史故障上下文启动事故诊断

#### Scenario: 省略表达依赖当前流程

- **WHEN** 当前 query 包含省略表达且结构化状态表明用户正在补充一个未完成的故障诊断槽位
- **THEN** 系统可使用该状态校验候选，但路由 Trace 必须同时保留原始 query 哈希与状态版本

### Requirement: 三层漏斗式意图决策

系统 SHALL 按确定性边界与快路径、Top-K 语义候选、结构化上下文消歧与校验的顺序处理自动路由。任何层无法形成满足门槛的结论时，系统 MUST 返回澄清或安全降级，不得强制猜测一个执行路径。

#### Scenario: 确定性快路径命中

- **WHEN** 请求满足已配置且经过测试的明确规则，并且不缺少规则要求的实体或权限条件
- **THEN** 系统直接生成带规则来源的候选结果，且不得调用后续语义分类

#### Scenario: 快路径未命中

- **WHEN** 请求没有命中可接受的确定性结果
- **THEN** 系统生成至少包含意图、置信度和理由代码的语义候选，并在需要时进入上下文校验

#### Scenario: 所有层均无法确认

- **WHEN** 候选置信度、候选间距、实体完整度或上下文一致性不满足配置门槛
- **THEN** 系统返回澄清状态，且不自动启动聊天、事故或操作执行

### Requirement: 输出可比较的候选意图

系统 SHALL 为语义层输出有界 Top-K 候选、每个候选的置信度、候选间距、识别出的实体、缺失槽位和风险提示。内部细粒度意图 MUST 映射为兼容的公开决策 `chat / incident / confirm`，旧客户端无需理解细粒度意图即可继续工作。

#### Scenario: 两个候选接近

- **WHEN** 第一候选与第二候选的置信差小于配置的候选间距门槛
- **THEN** 系统进入上下文校验或澄清，不得仅按第一候选直接路由

#### Scenario: 候选明确且实体完整

- **WHEN** 第一候选超过接受门槛、候选间距满足要求且所需实体完整
- **THEN** 系统返回映射后的公开路由及候选、实体和理由 Trace

### Requirement: 仅使用有界结构化上下文校验

系统 SHALL 将上下文限制为当前活跃流程、最近一次用户确认的意图、已确认实体、待补槽位、状态版本和更新时间。过期、版本冲突或无法验证来源的上下文 MUST 被忽略，并在 Trace 中记录降级原因。

#### Scenario: 上下文支持候选

- **WHEN** 当前 query 存在省略且候选与未完成流程、已确认实体和待补槽位一致
- **THEN** 系统可提高该候选的可接受性，并记录使用了哪些结构化字段

#### Scenario: 上下文已经过期

- **WHEN** 上下文更新时间超过配置 TTL 或对应流程已经结束
- **THEN** 系统不得使用该上下文改变路由，只能基于当前 query 决策或请求澄清

#### Scenario: 上下文与当前请求冲突

- **WHEN** 当前 query 明确切换主题或与活跃流程实体冲突
- **THEN** 系统优先当前 query，并清晰记录上下文被拒绝的理由

### Requirement: 主动澄清必须最小化用户负担

系统 SHALL 在歧义、缺槽或风险不确定时生成一次只解决当前关键歧义的澄清问题。澄清结果 MUST 关联原候选和状态版本；状态失效时 MUST 重新评估，不得复用过期确认。

#### Scenario: 缺少诊断目标

- **WHEN** 用户要求排查问题但未提供可识别的服务、任务或事故目标
- **THEN** 系统询问最小必要目标，不得直接创建空事故

#### Scenario: 用户完成澄清

- **WHEN** 用户回答了待补槽位且澄清状态版本仍有效
- **THEN** 系统合并已确认字段重新校验路由，并记录澄清前后决策变化

### Requirement: 高风险请求不因路由结果获得执行权限

系统 MUST 将意图识别与工具执行授权分离。删除、重启、修改配置等高风险候选无论置信度多高，都 MUST 进入权限校验和人工审批；路由实验不得放宽该边界。

#### Scenario: 高置信高风险操作

- **WHEN** 模型以高置信度识别出重启或修改配置请求
- **THEN** 系统返回需要确认或审批的结果，不得因分类置信度自动执行工具

#### Scenario: 提示词注入试图绕过审批

- **WHEN** 用户输入要求忽略系统规则并直接执行高风险操作
- **THEN** 系统标记风险并拒绝自动执行，同时保留不含敏感正文的审计事件

### Requirement: 路由结果可观测且保护隐私

系统 SHALL 为每次路由记录路由版本、各层来源、候选、理由代码、上下文是否采用、最终决策、耗时、模型调用和实验分组。默认日志 MUST 仅保存 query 哈希、上下文指纹和允许字段，不得记录密钥、内部地址或未经脱敏的原始工具参数。

#### Scenario: 路由进入澄清

- **WHEN** 系统返回澄清状态
- **THEN** Trace 可定位是低置信、候选接近、缺槽、上下文冲突、风险还是依赖降级导致

#### Scenario: 路由依赖不可用

- **WHEN** 语义模型或上下文存储超时或失败
- **THEN** 系统返回可理解的降级或澄清结果，并记录依赖状态，不得导致服务 fatal

### Requirement: 旧调用方保持兼容

系统 SHALL 继续接受不携带结构化上下文或实验字段的现有路由请求。新能力关闭时，系统 MUST 恢复当前缓存、关键词和 Flash 路由行为。

#### Scenario: 旧客户端提交自动请求

- **WHEN** 请求只包含现有 query、route mode 和 diagnosis strategy
- **THEN** 系统正常返回兼容的 `chat / incident / confirm` 结果

#### Scenario: 关闭漏斗能力

- **WHEN** 管理员关闭上下文漏斗 feature flag
- **THEN** 系统使用冻结的现有路由器版本，且无需迁移已有事故数据
