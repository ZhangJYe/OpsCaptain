## Purpose

让统一 Agent 入口和显式诊断入口按照用户选择安全地路由请求，并使返回的运行方式与实际执行策略可被前端准确展示。

## ADDED Requirements

### Requirement: 显式运行方式路由

系统 SHALL 支持显式 ReAct 问答、显式故障诊断和自动路由三种请求方式。显式 ReAct 问答 MUST 使用聊天链路；显式故障诊断 MUST 使用用户选择或 Flash 推荐且被允许的 Plan 或 GoS 策略。

#### Scenario: 显式 ReAct 问答

- **WHEN** 用户以 ReAct 问答方式提交请求
- **THEN** 系统使用聊天链路处理请求且不创建事故诊断

#### Scenario: 显式 GoS 诊断

- **WHEN** 用户以故障诊断方式提交请求并选择 GoS
- **THEN** 系统创建使用 GoS 策略的事故并返回该实际策略

### Requirement: 快路径优先的自动路由

系统 SHALL 在自动路由时按“近期路由缓存 → 高置信故障关键词 → Flash”顺序决策。缓存仅保存已经通过确定性校验的聊天或事故决策，并受配置的 TTL 与容量限制；系统 MUST NOT 缓存待确认、降级或无效结果。高置信故障关键词命中时，系统 MUST 直接返回事故路由，并使用用户固定策略或服务端默认允许策略，不调用 Flash。

#### Scenario: 命中近期路由缓存

- **WHEN** 自动路由请求与未过期的已校验路由结果匹配
- **THEN** 系统复用该结果且不调用 Flash

#### Scenario: 命中高置信故障关键词

- **WHEN** 自动路由请求命中配置的高置信故障关键词且不存在可用缓存
- **THEN** 系统返回事故路由，不调用 Flash，并使用用户固定策略或默认允许策略

#### Scenario: 快路径未命中

- **WHEN** 自动路由请求没有可用缓存且未命中高置信故障关键词
- **THEN** 系统调用 Flash 生成结构化意图与策略建议

### Requirement: Flash 意图路由与策略建议

系统 SHALL 在自动路由的快路径未命中时使用 Flash 快模型生成经过结构化校验的意图、策略建议、置信度和简短理由。Flash 只负责分类和推荐，不得调用工具、执行诊断或执行任何写操作。前端 MUST 根据已确认的路由结果调用既有的聊天流式入口或事故创建入口。

#### Scenario: 自动路由处理普通问题

- **WHEN** Flash 将自动路由请求识别为普通问答且置信度达到配置阈值
- **THEN** 系统返回聊天路由结果，前端使用 ReAct 聊天链路处理请求且不启动诊断

#### Scenario: 自动路由处理真实故障

- **WHEN** Flash 将自动路由请求识别为需要查询真实日志、指标或告警的故障，且用户将策略偏好设为 GoS
- **THEN** 系统返回事故路由结果并使用 GoS，前端创建事故且显示实际策略

#### Scenario: 自动策略选择 GoS

- **WHEN** Flash 将故障识别为多候选根因或需要证据支持与反驳，且用户选择自动策略
- **THEN** 系统返回 GoS 作为建议策略，前端使用 GoS 创建事故

### Requirement: 低置信度路由要求用户确认

系统 MUST 在 Flash 路由结果缺失、结构化校验失败或置信度低于配置阈值时返回待确认状态。系统 MUST NOT 在待确认状态下自动启动聊天或事故诊断。

#### Scenario: Flash 路由置信度不足

- **WHEN** Flash 返回的路由置信度低于配置阈值
- **THEN** 系统返回待确认状态，前端让用户选择继续问答或启动排障

### Requirement: 校验并降级不被允许的策略

系统 MUST 仅接受配置允许的诊断策略。对于缺失、未知或被禁用的策略，系统 MUST 返回可理解的降级或参数错误信息，且不得使用未声明的策略启动诊断。用户选择自动策略时，系统 MUST 对 Flash 推荐结果执行同样的校验。

#### Scenario: 请求指定未知策略

- **WHEN** 客户端为诊断请求提交未知的策略标识
- **THEN** 系统拒绝该请求并返回说明策略不可用的结果

#### Scenario: 请求指定被禁用策略

- **WHEN** 客户端指定的策略未被服务端配置允许
- **THEN** 系统不启动该策略并返回说明策略未开放的结果
