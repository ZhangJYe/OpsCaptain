## Purpose

让运维人员在一个清晰的运行配置界面中选择下一次请求的处理方式，并准确理解 ReAct、Plan 与 GoS 的职责关系和生效范围。

## ADDED Requirements

### Requirement: 展示分层的运行配置

系统 SHALL 在设置页提供“运行配置”入口，先让用户选择自动路由、ReAct 问答或故障诊断，再在自动路由和故障诊断场景中展示自动、Plan 与 GoS 的诊断策略选择。界面 MUST 明确说明 Flash 负责意图识别与策略建议，ReAct 负责问答执行，Plan 和 GoS 是互斥的诊断策略，而非固定串行步骤。

#### Scenario: 用户查看自动路由配置

- **WHEN** 用户选择自动路由
- **THEN** 系统展示 Flash 可将普通问答与真实故障分流的流程预览，并显示当前诊断策略偏好

#### Scenario: 用户选择 ReAct 问答

- **WHEN** 用户选择 ReAct 问答
- **THEN** 系统隐藏诊断策略选择并说明该模式不会主动创建事故诊断

#### Scenario: 用户选择故障诊断

- **WHEN** 用户选择故障诊断
- **THEN** 系统允许用户选择自动、Plan 或 GoS，并展示自动策略、Plan 与 GoS 各自的生效规则和适用特征

#### Scenario: 用户选择自动诊断策略

- **WHEN** 用户在自动路由或故障诊断下选择自动策略
- **THEN** 系统说明 Flash 将根据故障路径是否明确和候选根因数量推荐 Plan 或 GoS

### Requirement: 持久化下一次请求的运行偏好

系统 SHALL 保存用户选择的运行方式与诊断策略，并在应用重新打开后恢复该偏好。该偏好 MUST 只影响尚未发起的新请求；自动策略代表允许 Flash 为新诊断建议实际策略。

#### Scenario: 用户保存新的诊断偏好

- **WHEN** 用户将诊断策略从 Plan 切换为 GoS
- **THEN** 下一次新诊断使用 GoS，且设置页与工作台状态显示 GoS

#### Scenario: 用户重新打开应用

- **WHEN** 用户重新打开应用且本地存在有效的运行配置
- **THEN** 系统恢复该配置并在开始新请求前展示恢复后的状态

### Requirement: 已创建事故保持策略一致

系统 SHALL 在事故首次创建时记录实际采用的诊断策略，并在该事故的后续轮次中继续使用同一策略。设置页的后续修改 MUST NOT 改变已创建事故。

#### Scenario: 事故执行中更改默认策略

- **WHEN** 用户在 Plan 事故执行或查看期间将下一次诊断偏好切换为 GoS
- **THEN** 当前事故仍显示并继续使用 Plan，新建事故才使用 GoS

### Requirement: 工作台是唯一的新请求入口

系统 SHALL 将工作台作为用户提交新问题的唯一入口。事故记录 SHALL 只展示已经由 Plan 或 GoS 创建的诊断，且不得提供绕过智能路由直接创建事故的入口。

#### Scenario: 在工作台提交日常问题

- **WHEN** 用户在工作台提交日常问题
- **THEN** 系统按当前运行配置路由至 ReAct，且不创建事故记录

#### Scenario: 在工作台提交故障问题

- **WHEN** 用户在工作台提交故障问题并路由至 Plan 或 GoS
- **THEN** 系统创建事故记录，并在事故记录中展示该策略、过程、证据和结论

#### Scenario: 查看空事故记录

- **WHEN** 用户打开事故记录且没有已创建的事故
- **THEN** 系统仅提示用户从工作台发起请求，不提供直接创建事故的操作
