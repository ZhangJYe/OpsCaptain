## Why

目前的设置页只管理 MCP 工具、Skill 与通知；ReAct 问答、Plan 排障和 GoS 证据推理分散在不同入口，用户无法从一个位置理解或选择下一次请求的执行路径。需要把运行方式与诊断策略明确为可见、可持久化的用户配置，同时保留每个已创建事故的策略一致性。

## What Changes

- 新增“运行配置”设置页，集中展示自动路由、ReAct 问答和故障诊断三种运行方式。
- 在故障诊断相关设置中提供自动、Plan 与 GoS 的策略选择，并用流程预览解释它们与 ReAct 的关系。
- 自动模式先复用近期路由结果、识别高置信故障关键词；仅在二者均未命中时使用 Flash 快模型输出结构化意图与策略建议。故障发生时使用用户固定的策略或模型的策略建议。
- 将运行配置持久化为用户的前端偏好，并在新事故创建后锁定实际采用的诊断策略。
- 在设置页、顶部状态和事故视图中显示当前或已锁定的运行方式，避免 UI 与实际请求链路不一致。
- 将工作台收敛为唯一的新请求入口；事故记录只查看由 Plan 或 GoS 诊断创建的事故及其过程、证据和结论。

## Capabilities

### New Capabilities

- `agent-runtime-settings`: 让用户查看、选择并持久化下一次请求的运行方式与诊断策略。
- `agent-runtime-routing`: 让统一 Agent 和显式诊断入口按用户选择安全地路由 ReAct、Plan 与 GoS。

### Modified Capabilities

- 无。

## Impact

- 前端：`frontend/src/App.tsx`、设置页、顶部栏、输入入口、Chat/AIOps hooks 与类型。
- 后端：新增意图路由接口与应用服务，并复用现有 Chat 和事故创建入口。
- 配置：`manifest/config/config.yaml` 增加路由置信度阈值、允许的诊断策略、默认策略、路由缓存与高置信故障关键词。
- 测试：补充路由缓存、高置信故障规则、Flash 路由结构化输出、置信度边界与引擎偏好传递的 Go 测试，以及前端构建与浏览器交互核验。
